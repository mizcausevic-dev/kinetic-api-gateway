# Gateway review and pickup — 2026-09-29

## Decision

Keep this repository as a synthetic RevOps scoring API demonstration. The current code returns fixtures and recommendation text; it does not route leads, integrate with a CRM, or retain customer records. Build a real gateway only when there is a defined client, upstream service, and data ownership model.

## Remaining release gates and additions

1. **Before a public code release:** run the new branch's Node 20/22/24 tests, dependency audit, and CodeQL in GitHub Actions. The local fixes have not run on GitHub yet.
2. **For a stronger portfolio demo:** add one observable lead-to-account scoring example, either a documented client sequence or a dedicated read-only endpoint. Show that campaign fixtures are context, not a live reporting feed.
3. **Before real integrations or lead data:** define client and tenant authorization, limited scopes, signal collection purpose and consent, retention and deletion, log redaction, rate limits, request IDs, and audit events. Validate token audience if delegated access is introduced. Add idempotent event delivery, retries, and observable failure paths before claiming routing or automation.
4. **Documentation media:** `request-flow.png`, `scoring.png`, and the scoring screenshots depict older behavior. The current Mermaid diagrams and JSON example are authoritative until captures are regenerated.

## Ship and rollback

No deployment or public API endpoint was verified. This work is on a local review branch. To publish it for review, push `codex/gateway-review-fixes`, open a pull request against `main`, wait for all required jobs, then inspect the live result after merge. To leave the local changes without publishing them, run `git switch main`; the review branch remains available for recovery.
